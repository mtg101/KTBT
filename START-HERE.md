# KTBT: Start here

The short version, for a new chat (Claude) picking the project up. Read this and PLAN.md's **Next stages**; open anything else only for the part you're touching. It's kept short on purpose: add a gotcha when one bites, and nothing else.

## What it is

A Korean tent bar (pojangmacha) at night, as a reality show: the night runs itself (Godot 4.7.2, GDScript; customers, owner and talk from a local LLM through Ollama, or the canned AI offline), and the player is the show's PD (camera, plant cards, write-ins, pins, the edit). Pixel art drawn in code (`tools/art/*.py`) or from an image model, lit by a shader. See CONCEPT.md only if you need the design.

## Where things are

- `scripts/visit.gd`: the tent scene, ~7,300 lines. **Never read it whole**: grep its `# ---` section headers (The owner, The night, The edit, Let the crew run it, Tasks, Customers chatting, The cat, The PD's camera, The PD's plant cards, Building the screen, Regulars…) and read the section.
- `scripts/rules/`: pure rules and checks, no scene (talk, captions, cat_rules, hangul meanings, glossary, menu, ratings, ladder…). `scripts/ai/`: the AI (prompts, `canned_ai.gd`). `scripts/bar/`: parts of the tent (camera, pd_desk, night_stats, night_events, kitchen, street…). `scripts/ui/`: drawn things (people_art, pixel_light, transcript_view, crew_controls…). `scripts/save/`, `scripts/sound/`.
- `scripts/game.gd`: the autoload (`Game`): the open bar, saves, autoplay. `scripts/autoplay.gd`: batches and the crew. `scripts/debug_log.gd`: notes. `scripts/test_hooks.gd`: every test switch (`Hooks.*`).
- `tests/`: GdUnit4; scene tests extend `tests/support/bar_test.gd`. `tools/art/`: the art in Python (`people.py`, `tent.py`, `cat.py`, `light_preview.py` to look without Godot).
- The full map of files is ARCHITECTURE.md's "The files, by job": look up the one row you need.

## Gotchas (each cost a crash or a round trip)

- **Warnings are errors** (project.godot): a local or parameter that shadows a member, a base class's method or a global (`log`, `crew`, GdUnit's `before`/`after`, `owner`), an unused variable or parameter (prefix `_`), a `/` between two whole numbers (`@warning_ignore("integer_division")` on the line before when a whole number's meant, as the Python's `//`), a ternary whose two sides are different types (`x if ok else null`: write the `if`), and a `const X = preload(...)` named like a global `class_name` (`Ambience`, `Music`, `Bubble`, `Caption`, `LoadingScreen`: use them directly).
- **A PD's card on someone (or a chat, or the owner)** goes through `bar/card_slots.gd` (`CardSlots.plant`, `steer`, `owner_plant`; `use_plant`/`use_steer` when a line's given it), never by setting `plant_moment` or `pd_topic` directly: that wipes out a card still to come.
- **A new night event kind** goes in `scripts/bar/night_events.gd` KINDS, or `_event()` asserts and the game stops.
- **Notes:** `DebugLog.say("Kind", "...")`, never `print` (console kinds: `debug_log.gd` CONSOLE).
- **Hovers** go through `Text.tip`; **Hangul on screen** needs its meaning in `rules/hangul.gd` MEANINGS (or the glossary). The check reads a run of Hangul only across spaces and digits: "까악… 까악…" is two runs of "까악", so keep punctuation out of the middle of a key.
- **Clicks:** stage containers that only hold things (rows, layers) are `MOUSE_FILTER_IGNORE`, or they swallow clicks on whoever's behind them.
- **Tests:** a test file's count and the total are checked against TESTS.md and the README (`test_code.gd`); every script must appear in ARCHITECTURE.md or the README, every test file in TESTS.md. TESTS.md's line must read "All N tests pass".
- **Timing in scene tests:** the night carries on while a test awaits; don't assert on which exact line got something.
- **`_regulars()` fills the bar's list in** (RegularsTonight.all): reading it while a saved bar opens, before its upgrades, made an older bar look as if it had its founding regulars. Read `Game.bar.get("regulars", [])` there.
- **gdUnit's `assert_array().contains()` on a big array** (a portrait's grid) takes seconds: `assert_bool(array.has(x))` instead.
- **Freeing a child you'll look for again this frame:** `remove_child` before `queue_free`.
- **The helper (`tools/autoplay_mcp.ps1`) can't be tested here** (no PowerShell in the VM), and one parse error takes all its tools down until the desktop app restarts. In a string, `$name:` reads as a drive (`$env:`-style): write `$($name):`. `ConvertFrom-Json` in Windows PowerShell 5.1 hands a JSON list back as one item (and `@(...)` round it doesn't help): store it, then `@($parsed | ForEach-Object { $_ })`. Never name a variable after one of PowerShell's own (`$input`, `$args`, `$matches`, `$error`, `$host`...).
- **Godot in the VM:** the shell on the PC is a Linux VM, so it can't run the Windows Godot, but the Linux build in the user's Godot folder runs the tests headless on a scratch copy of the project (TESTS.md, "On Linux": copy the binary out of its folder to run it, pass `--headless --ignoreHeadlessMode`, and copy the user's `.godot/` in rather than importing afresh: thousands of faces take longer than a call, and a job left running in the background is stopped when the call ends); the user runs them too (VS Code, or GitHub CI). The whole suite fits in one call with `python3 tools/run_tests.py --godot <the copied binary>` run in the scratch copy (three shards, about two minutes in the VM; `--quick` while working, the full run before saying it's done). Copy to a new `mktemp -d` folder in `/tmp` (an old session's can't be written to), without `art/raw/` and its 2 GB of imports (left out while copying, or the copy runs out of space: make a list of the `.godot/imported/` files that `art/raw`'s `.import` files name, as `./.godot/imported/…`, and pass it to tar's `-X`; leave out `.godot/shader_cache` too: the copy's about 100 MB), and run the runner with `TMPDIR=$(mktemp -d /tmp/shards.XXXX)`: its shards' copies otherwise go on the session disk, which old sessions fill (26 Nov: out of space), and a fixed `/tmp/ktbt_test_shards` may be an old session's (PLAN.md has the fix). Also run it with `XDG_DATA_HOME=$(mktemp -d /tmp/xdg.XXXX)`: Godot's `user://` (saves, the autoplay summaries) is otherwise on that same session disk, and when it's full (26 Nov: 100%) test_bars and test_autoplay fail for no reason of their own. Delete that folder after each run (`rm -rf $TMPDIR` in the same call): each run leaves its shards' copies there, about 600 MB, and a few runs filled the disk (26 Nov). Nothing with a window. Godot's log is in the user folder (`…/Godot/app_userdata/KTBT/logs/godot.log`), test results in `reports/report_N/results.xml`, each night's notes in `logs/debug/`, transcripts in `logs/transcripts/`.

## How to work

- **Definition of done** (ARCHITECTURE.md has it in full): tests; counted in `night_stats.gd` (in its section); logged; docs (DEVLOG entry with the test count; PLAN.md only ever what's left; TESTS.md; ARCHITECTURE/README if a file or feature is new); Korean explained on hover; nothing private or branded.
- **A quick fix** ("quick fix" in the ask): the fix, a regression test if it can break again, a line in DEVLOG. No docs sweep.
- **Read little:** grep first, read the lines around the hit. DEVLOG is long: search it, never read it whole.
- **Art changes:** edit `tools/art/*.py`, run it (it writes `art/`, the manifest and LICENSE-ASSETS), check with `tools/art/light_preview.py`; the user imports in Godot.
- **Progress updates (often):** the app only shows "running a command on your machine" for commands here, so the user can't see what you're doing. On anything longer than a quick answer, send a one-line plain-English update (SendUserMessage) before every command or batch of commands, and never go more than about a minute without one: what you're doing now, and what's next. Before a command that could take over 30 seconds (tests, an import, ComfyUI), say what it is and roughly how long, and keep commands short (split long jobs) so the gaps stay small. Use a task list for anything with stages.
- **Commits:** the user commits from VS Code. When asked, update the docs and suggest a commit message (no private details; AI co-author line is fine).
